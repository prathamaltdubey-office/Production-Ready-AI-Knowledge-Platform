## Customer Churn AI

This document describes how the React frontend, FastAPI backend, ML prediction pipeline, and local AI chatbot communicate with each other.

# 4. CORS Configuration

The backend allows requests from the React development server.

The configured frontend origin is:

```text
http://localhost:5173
```

The configuration is implemented in `backend/api.py` using FastAPI's `CORSMiddleware`.

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:5173",
    ],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

This allows the React frontend to communicate with the FastAPI backend during development.

# 12. Pydantic Request Validation

Customer requests are validated using the `Customer` Pydantic model in:

```text
backend/schemas.py
```

Examples of validation rules include:

```python
gender: Literal["Male", "Female"]
```

```python
SeniorCitizen: Literal[0, 1]
```

```python
tenure: int = Field(ge=0, le=72)
```

```python
MonthlyCharges: float = Field(ge=0)
```

```python
TotalCharges: float = Field(ge=0)
```

This prevents invalid customer data from reaching the ML model.

# 13. Prediction Response

A successful prediction returns:

```json
{
  "prediction": 0,
  "churn_probability": 0.2938,
  "risk_level": "Low",
  "model": "random_forest"
}
```

### Response Fields

| Field               | Type    | Description                              |
| ------------------- | ------- | ---------------------------------------- |
| `prediction`        | integer | `1` means churn, `0` means no churn      |
| `churn_probability` | float   | Probability that the customer will churn |
| `risk_level`        | string  | Low, Medium, or High                     |
| `model`             | string  | ML model used                            |

---

# 14. Risk Classification

The backend converts the churn probability into a risk level.

### High Risk

```text
probability >= 0.70
```

### Medium Risk

```text
0.40 <= probability < 0.70
```

### Low Risk

```text
probability < 0.40
```

Example:

```text
Churn probability = 0.2938

0.2938 < 0.40

Risk Level = Low
```

# 15. Model Loading

ML models are loaded through:

```text
backend/model_loader.py
```

The saved models are located in:

```text
models/
```

The mapping is:

```python
MODEL_FILES = {
    "logistic_regression": "best_logistic_model.pkl",
    "random_forest": "best_rf_model.pkl",
    "xgboost": "best_xgb_model.pkl",
}
```

The model loader verifies that:

1. The requested model exists.
2. The model file exists.
3. The loaded object is a Scikit-learn `Pipeline`.

This ensures that the same preprocessing and model logic used during training is used during inference.

# 17. Prediction Error Handling

The prediction endpoint handles invalid model requests.

If an invalid model is requested, the backend returns HTTP `400`.

Example:

```json
{
  "detail": "Unknown model: invalid_model"
}
```

Unexpected prediction errors return HTTP `500`.

Example:

```json
{
  "detail": "Prediction failed."
}
```

Errors are also written to the backend logs.

# 20. Chat Request Validation

The backend validates chatbot messages using:

```python
class ChatRequest(BaseModel):
    message: str = Field(
        min_length=1,
        max_length=2000
    )
```

Therefore:

* Empty messages are rejected.
* Messages longer than 2000 characters are rejected.

# 32. Chat Response Parsing

The parser is implemented in:

```text
chatbot/parser.py
```

The function:

```python
parse_response()
```

attempts to parse an LLM response as JSON.

If valid JSON is received, it is validated against:

```text
ChatResponse
```

If the response cannot be parsed, the parser falls back to a normal text response with:

```text
confidence = 0.0
prediction = null
```

This prevents malformed LLM output from crashing the application.

# 47. Key Design Decisions

### Separate frontend and backend

React is responsible for presentation while FastAPI handles application and ML logic.

### Saved ML pipelines

The entire Scikit-learn pipeline is loaded rather than manually reproducing preprocessing during inference.

### Pydantic validation

Invalid customer inputs are rejected before reaching the model.

### REST API

Prediction and chatbot functionality are exposed through clear HTTP endpoints.

### Local LLM

Ollama and Llama 3 allow the chatbot to run locally.

### Structured chatbot output

Chatbot responses follow a predictable Pydantic schema.

### Logging

Important API operations and unexpected failures are logged.

### Swagger

FastAPI automatically provides interactive API documentation for development and testing.
